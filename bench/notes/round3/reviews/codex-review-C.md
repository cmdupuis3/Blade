## Numbered findings

1. **BLOCKER — N09 changes the benchmark to fit Blade's implementation.** Section N09 says “the spec therefore names [T1/T2] as required intermediates, stored in every arm.” The catalog names only Y as output and explicitly permits temporary-layout/scheduling choices. Source `n09:40–45` fixes the contraction DAG, not an entitlement to force the expert to retain both full tensors. Moreover, “deferred T1 necessarily costs O(n⁵)” ignores by-name forcing (finding 4).
   **Fix:** require stored X/A/B/C and Y only; preserve the three mode contractions and their scalar chains. Let all arms choose legal intermediate lifetimes/layouts. If a materialized-T1/T2 control is useful, give it a separate spec, not N09's headline.

2. **BLOCKER — N02's proposed five-contribution expert is not the specified strict AD reference.** `n02:32` contains `(0.5*x(-2))*x(-2)`. `GradSweeps.adjointOf:236–239` differentiates both occurrences separately. `haloGather:356–366` sorts **assignments**, not unique offsets, and emits one pass per assignment: six x updates, plus the wt-gradient update, before considering other passes. At offset −2 the two rounded addends are structurally `((-w)*x)*0.5` and `(-w)*(0.5*x)`; collapsing them to one `-w*x` update changes the accumulation chain. Descending offset alone does not specify the repeated-offset ordering. The brief's five-pass/roughly-seven-total-pass model is therefore wrong.
   **Fix:** write the analytic reference as an explicit ordered update list, including both −2 occurrences, +0 initial dx, source multiplication parentheses, skipped nonexistent windows, and stable order within an offset. Make both Fortran twins use it. Alternatively define a separate simplified-derivative S algorithm and change Blade to that algorithm too. The original catalog supplies no particular F or five-term derivative formula; do not invent one by treating emitted AD as the independent oracle. `dw` can supply y only via its interior slice, with the y stores audited; it is an n-cell gradient with zero boundary cells, whereas current y has n−4 cells.

3. **BLOCKER — N06's “exactly antisymmetric / order-identical” claim exceeds its source.** `n06:35–37` evaluates `w(i,j)*(x_i-x_j)` independently in each direction and includes j=i; the catalog defines p once at canonical i<j and reconstructs the other endpoint by negation. On this finite fixture, with separate products and contraction off, the ordinary nonzero contributions agree and canonical lexicographic traversal gives each row's ascending-neighbour sequence. That does **not** establish the same rounded program under fast contraction: an endpoint `acc-p` after p is rounded need not equal an independently contracted `acc+w*d`. Private-buffer/thread-order merging or coloring also does not preserve each row's serial chain merely because thread IDs are ordered. The extra self +0 and implicit first-element seeds need an explicit policy.
   **Fix:** freeze canonical p's expression, exclude self interactions, specify endpoint seed/order and rounding points, and pin the signed reconstruction against an independent oracle. Use an order-preserving serial/owned-output repro reference; give reordered private-buffer merges only the applicable licensed regime (or explicitly label the protocol's repro-mt8 asymmetry). Remove `sum f(:,0)` from the checksum as already proposed; retain it only as a separate validation invariant.

4. **HIGH — N06's ranking rests on an unverified and contradicted cost model.** A named deferred array is not a promise of re-evaluation at every index. `CodeGenFusion.collectDeferredPositionalReads:1607–1643`, `collectDeferredKernelCaptures:1690–1697`, `CodeGenBinding.genComputeBinding:1061–1068`, and the function-body forcing logic `CodeGen.fs:183–212` force by-name/captured reads. `loops/129_deferred_binding_captured_by_kernel.blade` pins this behavior, including positional reads. Thus one must distinguish a packed weight pool, a scope/emission failure, and actual recomputation; **18.8M phi evaluations is not established**. A forced symmetric pool at n=2503 has 3,133,756 cells, including diagonal, about 25.1 MB; the Newton expert has 3,131,253 off-diagonal pairs.
   **Fix:** delete the 6× work claim and derived 4–6× loss forecast pending later emission/allocation evidence for this exact function scope. Identify the consumer IR actually reached before claiming it exercises a *deferred* endpoint transformation. Keep compiler-created pair storage as overhead, never promote it to a required output.

5. **HIGH — N05's expert violates its data dependencies.** “Solve all 2r RHS … in one triangular sweep” cannot compute dX: its RHS depends on the completed primal X through EX (`n05:42–44`).
   **Fix:** factor once; batched r-RHS primal solve; ordered EX/R formation; batched r-RHS tangent solve. Reuse the factor and packed panels across both phases, vectorizing independent systems/RHS. Define the strict-`>` pivot tie and elimination/solve operation sequence from `math/083`; a generic GETRF/GETRS description is not an exact arithmetic specification. Natural factor-once scalar RHS calls are credible. Do not permit natural to refactor per RHS. Add ill-conditioned/singular/pivot-tie validation separately; current permuted dominant fixture only exercises a well-conditioned regime.

6. **HIGH — N03's numerical algorithm and natural arm are not frozen together.** `n03:50–56` starts with −1e300 and executes the merge for the first key; the catalog explicitly installs the first score/value without exponentials. For the current nonnegative finite scores/values, the dummy merge underflows ca to zero and reproduces that first state, but performs different work and is not a general −∞/empty-row implementation. `n03:36` uses 0.0208333, not 1/48. The proposed natural two-pass stable softmax is explicitly a different algorithm, not an R twin.
   **Fix:** implement the catalog's first-key branch and exact `1.0/48.0` threshold, or explicitly freeze a finite-fixture alternate algorithm in every compared arm. Use an unblocked online recurrence as natural; keep two-pass as a separate S comparison. Pin singleton/segment boundaries and every vector component/log normalizer. Record the topology in input validation. Compute P exactly from `sum(i-st(i)+1)`: under an IID geometric break model of mean length 48, expected causal pairs are approximately **48N**, not 24N; the brief's 4.9M estimate assumes roughly fixed-length segments.

7. **HIGH — N04's natural twin is deliberately unfair and cannot fit its full size.** A (20012)² Int64 table is about **3.20 GB**, before inputs, against the 64 MB rule. A band predicate does not fix its allocation or dense iteration cost. The “drop if expert/natural <1.5” criterion tests a strawman.
   **Fix:** natural = straightforward banded row-major DP with two band buffers and explicit clipping; expert = peeled/branch-reduced band bounds, vectorized independent batches if separately specified. Keep the full-table implementation only as a tiny oracle. Freeze `0<=w<=n`, finite costs and `inf > maximum attainable score`; row0 currently does not clip j>n (`n04:36`). For admitted sizes, `:47–50` has the correct previous-row coordinate shifts; returning inf instead of inf+1 for an absent up/left cannot win against the finite valid path. Declare that sentinel convention and second-argument-on-tie `imin`; do not claim an implicit-zero bug where the guards already prevent one.

8. **HIGH — Storage and 64 MB claims are payload estimates, not working-set acceptance.** All required numerical outputs are traversed by the source checksums: Ufinal; y/dx; O/log-normalizer; valid DP row/score; XD; f; y1/y2; pay/sens; Y; cost/grad/H. N10's H checksum visits off-diagonal packed cells twice through their logical mirrors; the expert must match that weighting. `|> compute` and a scalar checksum do not prove physical stores (`bench/README.md:58–67`).
   - N01 cap-size trajectory is ~52.34 MB plus input/output/scratch/row tables. The proposed 1501×2003 size needs **24.05 MB per plane**: retained u0 plus two work planes already costs **72.16 MB**. The source computes kernel(u0) before its input sum, so u0 remains live; “two 24 MB planes” omits it.
   - N02's “six arrays =48 MB” counts y and loss-local d together while omitting d's cotangent (`Grad.fs:391–403`). Local lifetimes, retained pools and AD temporaries determine the actual peak; six source names do not prove the budget.
   - N03 is ~32 MB Q/K/V plus ~1.6 MB starts and ~8 MB output, before scaffolding. N04 is ~32.5 MB DP plus inputs. N05 is ~38.1 MB principal input/output payload. N07 is ~48 MB principal payload. N08 is ~48.35 MB trajectory plus states/draws/outputs. N09 is ~27.9 MB four tensors plus factors. N10 is ~35 MB including inputs, r/jt and packed outputs. None includes all runtime overhead.
   **Fix:** resize N01, and provide per-arm peak-live allocations including thread scratch and row metadata, followed by the protocol's later full-size store/working-set audit. Do not run that audit during this timing session.

9. **HIGH — N10's proposed optimization and its forced source tapes disagree.** `n10:44–45` explicitly computes r and jt; the advertised gain then removes “the r and jt tapes.” Under the preamble's “only compiler-inserted temporaries may disappear,” these are not unnamed compiler temporaries. The catalog explicitly requests no per-sample Jacobian output.
   **Fix:** list only cost, gradient and packed H as named outputs. Express residual/derivative producers with the highest available deferred/shared-summary idiom so any incidental pools are compiler-inserted, or retain the forced-tape spelling as a separately identified materialized control. Do not force Fortran to keep tapes to excuse Blade's source choice. State that this is hand-derived, rectangular-group N10; add ragged/generated-AD variants separately. Five source-level exp evaluations per sample is not yet an emitted-code count: invariant motion/dead-code elimination may change it.

10. **HIGH — The common regime/size claims miss actual source choices.** The protocol says no power-of-two extent **anywhere** (`bench/kernels/README.md:111`); N03 uses D=8/V=4, N05 and N08 use Two=2, N10 uses P=4. Those may be sensible semantic component counts, but “no power-of-two extent” is false. N03's regimes also differ in its score `prodsum`, not only checksum. N10 threads residual/Jacobian construction but has **no outer omp** on cost/grad/H maps (`:46–48`); N08 has none on spots, the step or final maps. N09 leaves factor generation serial. Builtin fold licensing is not automatically a thread request.
    **Fix:** choose non-power-of-two tunable feature widths or record an explicit protocol exception for fixed semantic component axes; do not pad away meaning. Add legal outer licences to independent maps/generation/checksums and document each loop's actual form. None of these files has captured writes inside an omp body; do not misclassify local scratch/AD output buffers as races. Keep the catalog's exact fold order in repro; state licensed permissions per fold, and label vendor fastmath unequal as the bench protocol requires.

11. **MEDIUM — Inputonly policy is asserted rather than justified.** The rule is **input share >5%**, not “bandwidth-bound” or “exp-bound” (`bench/kernels/README.md:248–255`). N02/N05/N07 get twins; N03/N10 are denied them without attribution despite substantial generated inputs. N01's 5% assertion is unmeasured.
    **Fix:** provision matching inputonly arms for N03/N10 and retain them if the later pilot exceeds 5%; apply the same threshold to every other candidate. Include N03 topology construction and an input checksum/pin that actually observes it. N08's addressed draws are part of the path algorithm, not removable generic input setup; its ordinary s0 generation is the inputonly candidate. Report total-minus-own-twin only as the protocol's incremental estimate.

12. **MEDIUM — N08's address and step-count contracts need one missing distinction.** `n08:30` gives disjoint intervals [t·np,(t+1)·np) for fixed global np; there is no address collision in the proposed finite domain. It is not invariant under replacing np with a chunk width. `:39–44` uses nt−1 draws/updates although the prose says S(T).
    **Fix:** name total global path count P, chunk base p0 and step count T separately; a chunk uses offset t·P+p0 and its own fill length, with T+1 trajectory rows. Alternatively explicitly define T=nt−1 in all arms. Pin chunk/restart identity at odd offsets. The expert may tile paths and fuse tangent state, but must port exact Philox word arithmetic/uniform conversion/Box–Muller sample addressing; signed integer(8) multiplication plus masks is not by itself a defined unsigned 32×32 product. Compare raw words bitwise and transformed values under the declared libm tolerance.

13. **MEDIUM — N07's mechanism and drop criterion need rescoping.** Resident Chunked storage does not make actual chunk reads or ghosts. The source is two flat interior maps; it cannot measure retained-overlap I/O. A 17-cell ring is an expert candidate, not a guaranteed win over direct fused loads.
    **Fix:** call this the resident two-output FIR/sibling-map experiment. Natural two slice statements and expert fused direct loops are credible; evaluate a ring only as a reviewed alternative. Handle y1's six-only fringe centres outside y2's domain; retain separate +0 prodsum chains and combine s1+s2. A file-backed ghost-reuse benchmark needs its own provider/cache protocol. Do not drop a useful control simply because its measured fusion gain is <10%.
