# D06 source/design census: first private sequential intermediate

Design only, 2026-10-22. Lane base `029448fe4b74de57b75ed50afd2755661dca93a1` (accepted D05; integration `b6f4beec`, runner 600 Zarr passes / 0 failures / one existing internal NetCDF skip). No production/test edits, compiler execution, emission, build, benchmark or commit accompany this census. D05 sources and documents stay frozen.

## Recommendation and prerequisite

There is a useful missing ST09 route: one private computed Float64 stream, a global statistic, then a transformed scalar terminal. It can remove a resident producer pool without rereading an external source or changing the two-pass arithmetic graph. However, the current runtime has no mandatory spool, scratch grant, disk reservation or scratch recovery owner. Do not admit omission of the pool until that ownership/resource protocol exists and passes fault tests. The next implementation card should be that narrow runtime prerequisite with an explicit harness-supplied grant, not an automatic/default spill policy or a partially wired optimizer route.

Root's refinement applies: the first route ends in a scalar. A stored normalized output is not required by this witness. If a program demands a stored array, that demand must retain its resident allocation and is outside this pilot.

The governing design is `integration/bench/notes/peakmem-streaming-optimizer-plan.md` section 5.2 (lines 272-317), ST09/S4 (458/477), and its route/fault gates (521-535). PM12/13/46 in `peakmem-microkernel-plan.md` (345-346/399 and section 5.11 at 672) distinguish identical two-pass evaluation from a new online algorithm. The local SIMD microkernel sketches do not provide a spool owner or authorize a different normalization formula. This card does not use Welford, online softmax, source replay or a public sink.

## Concrete Blade idiom and current source route

The existing `tests/corpus/memfree/022_scratch_reuse_dead_pools.blade:25-30` already writes a stored pure producer, a global mean and a centered transform. `tests/ZarrTests.fs:1157` uses seeded scalar reductions; its existing streamed-map tests establish the provider/map syntax. The proposed combined witness is this ordinary composition (shown for design, not newly typechecked or emitted):

```blade
import zarr as z
let s = z.load("fixture.zarr")
let A = s.vars.A |> z.stream
let p = method_for(A) <@> lambda(x) -> x * x + 1.0 |> compute
let m = reduce(p, (+), 5.0) / Float64(extents(p))
let result = reduce(method_for(p) <@> lambda(v) -> (v - m) * (v - m), (+), 3.0)
```

Select only `result` for printing; otherwise the default print of computed `p` is a real stored-value demand and prevents this optimization. The nonzero seed makes `m` a deliberately shifted mean and exercises both original chains. A small rank-one f8 Zarr v2 fixture with x=[1,2,3,4,5], physical C=2 gives p=[2,5,10,17,26], sum seed 5 -> 65, m=13, transformed cells [121,64,9,16,169], result seed 3 -> **382**. N=1, x=1 gives **28**. These are hand-derived pins, not runtime observations. Empty N=0 must preserve evaluation of 5.0/0.0 and then the empty final fold seed 3.0; no frontend Chunked zero-extent syntax is needed.

## Proposed first region boundary (after the runtime prerequisite)

One ordinary top-level serial host region, one local ordinary uncompressed dense rank-one f8 Zarr source, one private computed Float64 producer with literal-coefficient closed scalar +,-,* arithmetic, one seeded Float64 sum divided by its static extent, and one total centered-square seeded scalar sum. Require the existing index identity and matching static nonnegative extent; initially reuse rank1TerminalChunk's conservative representable shape/chunk capability (ZarrProvider.fs:2202-2220), but do not reuse its different validation boundary. No codecs, packed/virtual/masked/windowed or allow-missing source, multi-file/Icechunk/multi-provider input, rank-two rows, variable-width values, RNG, recursion, mutation, general callbacks, captures other than the certified statistic operand, MPI, OMP, CUDA, LLVM or interpreter stream admission.

Admission must finish before omitting ANY binding or allocation. Use actual binding positions for dominance/order. The full merged program census must include binding values and side operands, function bodies and captures, all binding/function/module Types extent payloads, name-only roots, provider reads/writes, printing, aliases/views and foreign-module uses. `Optimize.bindingPayload`, `compactionRoots`, `moduleReferencedIds` (1484, 3635, 3662) are the shared seams; this lane's older compactionRoots lacks integration C01's module Types supplement, so do not copy it as a complete census. Root already removed the D01 temporary supplement on integration; this card changes neither version.

Reject conflicting PoolReuse/HotRow/Compaction/CompactRow/tile/other storage owners or agree one owner before codegen. Keep a certificate tied to exact original binding/kernel/source identities and the authorized whole-program emission. Nested local genBinding, direct genModule/genModuleSplit and generic provider calls have no grant. No mutable current-ID cell and no omission based on binding numbers. Required p print, explicit array output, escape/capture, side-use or intervening fallible/effectful statement declines the complete region. A policy-disabled soft choice uses the ordinary resident route; an explicitly requested hard budget that cannot support either legal strategy must deliberately refuse, not silently exceed the budget.

## Arithmetic, provider validation and failure order

The original value graph is p once, statistic over the stored p cells, scalar m once, then ascending transformed cells and their seeded sum. Under BLADE_FP_REPRO=1 each fold must keep its original seed, operand order and association continuously across blocks; no block partial sums. Decline unsupported licensed/fast fold forms rather than claiming an identical FP graph. Preserve the chosen build's contraction policy and the Float64 materialization boundary: evaluate each p cell into the exact stored-width representation, fold that value and spool those same bits. Replaying the value must not re-evaluate x*x+1 or contract the producer with the consumer. Producer/statistic/transform/terminal and seeds must pass a concrete closed purity/totality audit (`IRTotality.fs:12-25, 121-174` plus the narrower selected scalar grammar). Integer division, float-to-int casts, lgamma/digamma, panic, array access without a bound proof, unresolved calls, writes or other effects decline. IEEE Inf/NaN produced by total float arithmetic are values, not a new spool missing-value error; no NaN or signed-zero canonicalization is allowed.

For the selected `.stream |> map |> compute` baseline, use EXACTLY the same natural C-sized windows, in the same order, through GenStreamRows. `ZarrProvider.fs:2234-2242` calls genStreamWindowCore, whose per-window scan is at 2182-2193. A window is fully filled and validated before any of its producer cells are used; global diagnostic origin remains the window origin. The padded physical chunk scratch and its short/null-chunk errors remain unchanged. An earlier window's missing value wins before a later short/null chunk is visited. This differs intentionally from whole `.read`/D01 terminal tally semantics (2223-2228), where later chunk I/O may precede the final missing report. Do not substitute genStreamRowsTerminal or claim those two baselines have the same failure order. Finite fill, endianness and odd padded tail behavior remain provider-owned.

Totality permits accumulating the statistic while producing p, but it does not certify provider I/O. Complete all original source reads/validations before computing m or replaying; no result is published early. There is no second source read and no source immutability assumption: replay reads the uniquely owned computed spool bytes only. Size/mtime in blade_run_record.hpp:30-35 remains observation, not snapshot identity.

New resource/I/O failures require an explicit precedence contract before admission. Suggested narrow rule: policy/checked-size denial is a pre-execution resource refusal; once source consumption starts, latch the first spool create/append/flush/close failure and continue the original source window/validation sequence using the already reserved bounded input buffers, disabling further spool writes. Report that latched spool fault only if all source reads/validations succeed. This prevents an early short write from concealing a later original source diagnostic. If this drain-on-spool-failure rule is not implemented/tested, the provider-backed route remains declined. Replay/integrity errors occur only after successful production; final scalar publication waits for full replay, footer/EOF checks and normal scratch cleanup. A prior unrelated printed binding stays printed as before; no whole-program transactional stdout guarantee is invented.

## Explicit resource and format contract to review

These are proposed contracts, NOT existing flags/defaults:

- An explicit per-run grant supplies an absolute declared scratch root, tracked workspace byte allowance, disk quota, fixed block capacity, bounded path/descriptor sizes, and cancellation/recovery policy. No grant means no disk route. An internal harness can supply this typed grant for the prerequisite; adding a CLI/toolchain setting requires separate review. Read any eventual environment/toolchain configuration per call, not a cached compiler flag.
- One active intermediate and generation; no compression, shared writers, fanout, random-access catalog, implicit OOM retry or hybrid migration. Proposed B=C for the first region. Capacity ledger conservatively includes converted input 8*C, producer/replay buffer 8*B, padded disk decode 8*C, fixed I/O buffers/headers/checksum state, handles, paths and ownership manifest. With B=C, payload workspace capacity is at most 24*C plus explicitly bounded metadata. Reuse/free can tighten actual lifetimes later; no uncounted vector capacity, stdio buffer, thread cache, or page-cache/RSS claim.
- Removed logical resident intermediate is p=8*N bytes; the final required result remains one scalar, plus its statistic state. Input files and spool are still real disk storage. No result-array allocation is evaded. If p fits better resident, no performance superiority is asserted for spooling. Existing pool retention constants (`nested_array_utilities.hpp:104-133`, Toolchain.fs:216-270) limit released-pool caches per thread; they are not a hard program workspace budget or scratch grant.
- Fixed-size file header H, one constant-size block header h per block, exact 8*n_i payload bytes and footer F. Require 8-bit bytes, sizeof(double)=8 and an IEEE754 representation; decline unsupported hosts before creating scratch. Let G=N/B + (N%B != 0), computed without N+B-1 overflow. Check H+G*h+8*N+F and bounded manifest/directory accounting using wide checked arithmetic before narrowing; reserve that full amount against the declared per-run quota before writing. One active generation avoids unreserved overlap. Logical quota reservation is not a physical free-space guarantee: ENOSPC still has checked failure semantics. A shared-root aggregate quota, if desired, needs a separately locked allocator; per-run grants do not claim that property.
- A versioned, explicitly encoded header records fixed-width IEEE754 binary64 little-endian representation, N, rank-one axis/descriptor identity, B, expected G and a run nonce. Serialize value bits, never C++ structs/padding/pointers or textual doubles. Each block includes sequence, logical origin, element count, payload length, nonce/descriptor association and an incremental integrity checksum. Expected origin/length/sequence are arithmetic; no per-block vector/table/map is kept. Footer records final counts/bytes and rolling integrity result. N=0 is a header/footer-only spool. Corrupt nonfinite values are detected as changed bytes; valid nonfinite payloads remain valid values. This is accidental-corruption detection, not authentication against an adversarial writer.
- Reads/writes loop on returned byte counts, handle interrupt/error status, reject zero-progress and any uncompleted short transfer, and check flush, close, all length/offset conversions and I/O seek limits. Sealing requires successful footer write, flush and close; no reader opens an unsealed file. Reader checks exact sequence/origin/tail length, checksums, totals, footer and EOF/no trailing bytes, validating each block before applying its transform. Successful replay has no durability promise across machine crash; fsync durability is not claimed.
- Expected bounds: one data handle (writer OR reader), one ownership lock, at most one transient manifest handle and one provider chunk handle, hence at most four simultaneously, with explicitly sized I/O buffers. Disk high water, payload write/read byte counters and active buffer capacity must expose route evidence. Do not register one metadata object or cleanup callback per block. Provider compile-time storeFiles/fingerprint (ZarrProvider.fs:1272-1299) can still enumerate source files: bounded spool metadata is not bounded total compiler memory.

## Unique owner and exit/recovery protocol

State machine: Granted -> Owned/Writing -> SealedClosed -> Reading -> ReplayChecked -> Removed, with Faulted/Cancelling -> Cleanup. One writer is uniquely moved into a sealed token; that token creates one replay reader only. Calls in the wrong state, double seal/replay and sequence reuse are errors. Creation uses a fresh nonce and exclusive creation in a private run directory with an ownership manifest containing facility/version, nonce, PID and process-start identity. A live exclusive lock covers writer, gap between close/open, reader and deletion. The immutable manifest/known filenames and lock state are bounded; do not close ownership during replay or expose the spool as a normal Blade Array/provider handle. Files must remain under the declared owned directory; no cleanup follows a symlink/reparse point outside it. A lock alone is not a source snapshot.

Existing cleanup evidence matters:

- `blade_tilecache.hpp:142-192` treats invalid/short entries as disposable cache misses. `store:224-242` can ignore open/write/flush/close/rename failure. Neither API is a mandatory-intermediate protocol; reusing it would silently lose the value that replaces p. Its unique temp name is not an ownership lock, quota reservation or recovery proof.
- `blade_runtime.hpp:347-389` uses std::_Exit after its private failure_exit_hooks[8]. RAII destructors and atexit do not run there. Existing registration silently runs out of slots; the prerequisite must establish checked successful registration of one idempotent cleanup hook, never assume a ninth hook was registered.
- Zarr's zExit and short/null paths (`ZarrProvider.fs:1372,1425,2163`) use std::exit. These require normal-exit/atexit cleanup as well as the panic hook. `CodeGen.fs:3483-3493` already registers NetCDF finalize through both exit mechanisms; `blade_run_record.hpp:294-314` is another model for dual normal/failure handling.
- Generated main catches C++ exceptions through panic (`CodeGen.fs:3626-3634,3710-3715`), so the owner must be registered before the first provider read. A process-stable, fixed-capacity active-owner slot must not retain a dangling stack pointer after normal cleanup. Cleanup is idempotent; double paths and repeated regions cannot delete another run's file. The serial pilot avoids a concurrent worker doing cleanup during writes.

Normal completion explicitly closes the reader, removes only owned files, releases quota and lock, and only then publishes the terminal. If removal fails, do not report Removed or claim the occupied disk bytes were reclaimed; preserve the manifest/reservation information for recovery and report the cleanup failure. Normal failure/cancellation uses that same cleanup plus the registered exit hooks as a backstop. Provider/panic primary diagnostics cannot be replaced by secondary deletion failures; failed cleanup remains recorded/visible for recovery, not reported as successful deletion. A cleanup callback must avoid throwing/allocating/panicking recursively. Runtime spool operations should return structured status; the GENERATED call site invokes the diagnostic with its Blade span. `tests/Test_Diagnostics.fs:245-300` forbids new runtime headers from calling blade_rt::panic invisibly because shadow-frame elision depends on textual generated calls. Diagnostic codes/messages for resource/quota/format/I/O/ownership failures remain a review decision; this census assigns no invented BL code.

Cancellation is cooperative at safe block boundaries (a signal handler may set a flag, not run filesystem cleanup). An uninterruptible provider call may delay it. Forced kill, abort, terminate, host crash and external _Exit bypass the registered path and can leave owned scratch; do not promise otherwise. Recovery is explicit, not an age-based sweep: restrict to this facility's recognized manifest/version and owned root, acquire the exclusive ownership lock, and prove the recorded PID plus process-start identity is dead before deleting. If liveness/identity/lock certainty is unavailable, retain and report. A live concurrent run, PID reuse, malformed/partial manifest and unrelated directories must never be removed. OS-specific lock/liveness support is a capability; unsupported platforms decline this disk route rather than using a weaker lockfile convention.

## Proposed one-card implementation scope and bounded gates

**Minimal prerequisite card for root review:** implement only a private fixed-width sequential runtime writer/seal/reader/cleanup owner with an explicit test/harness grant, quota/format validation and fault seams. Do not yet omit compiler bindings, add automatic strategy selection or expose a public spill/sink API. Candidate files: a new narrowly scoped `src/cpp/blade_private_spool.hpp`, checked failure-hook integration in `src/cpp/blade_runtime.hpp` if needed, explicit runtime deployment entries in Blade.fsproj (existing headers are enumerated around 769-780), and a dedicated focused harness/spec plus docs. Preserve the panic-header tripwire. There is no provider write API change. Avoid touching CodeGenLoopNest's memory owner for an unrelated file protocol.

After that prerequisite passes, the first ST09 admission would use CodeGenState's explicit whole-program context and a separate exact region plan consumed by CodeGenBinding/CodeGen, with all-or-nothing omission of p/statistic/final terminal under that plan. It must coordinate existing epilogue owners before generation, retain the disabled-policy resident path, and assert no p allocation/no O(G) run table plus actual spool traffic. This later region work is not authorized or implemented by this design checkpoint.

Bounded tests to author with the appropriate card, not run now:

1. Runtime protocol: N=0,1 and odd tails at B=2/3; exact byte round trips including -0, +0, subnormals, Inf and NaN payload bits; header/version/representation/shape/nonce/sequence/origin/length/footer/trailing-byte failures. Use tiny files; huge lengths are checked metadata-only cases and must never allocate/execute huge resident outputs or create huge files.
2. Quota/memory preflight: exact-fit vs one byte short including all metadata; overflow in N*8, G*h, summed file bytes and stream offsets; invalid/absent grant, root or B; fixed buffer/handle/catalog high-water counters with increasing SMALL block counts. No malloc-then-OOM fallback. Simulated disk-full, partial/zero-progress write/read, flush/close/reopen/truncation/checksum faults must produce deliberate status, no replayed partial value, and correct quota/owner release or retained recovery record.
3. Lifecycle: wrong-state calls, no reader before successful seal/close, one reader token, double cleanup, failure-hook registration exhaustion, normal return, std::exit, panic/_Exit, caught exception and cooperative cancellation. Child-process forced kill/abort recovery must distinguish expected leftover scratch from successful cleanup. A live concurrent owner and PID-reuse/unknown-liveness/foreign-directory controls must survive recovery. Bound all child runtimes and file sizes; no actual host disk exhaustion or unsafe stale sweep.
4. Later route census/gate: capture the ordinary witness's IR/C++ allocation with result-only print selection, then verify emitted marker AND observed bytes written/read on the spool route, materialized reference values 382/28, independent odd-tail pins, strict nonzero seeds, empty fold behavior, no array pool/run table for p, scalar output still published, and source read count/window order unchanged. Compare .read only for successful values; use the original streamed map route as the failure-order oracle.
5. Later negative regions: demand/print p, stored output, escaped alias/view, type/extent/capture/side-table/foreign-module use, differing axis, mutable input/capture, another storage owner, unsupported FP licence/backend/provider/codec, stat/transform panic and stale certificate all decline without losing a resident allocation or returning runnable unsafe code. In particular pair an early statistic panic with a later provider failure to prove the totality gate declines the otherwise reordered program.
6. Later provider fault pairs: early window missing vs later short/null chunk, same-window short vs missing, finite-fill/endianness/padded-tail controls, plus an injected early spool write failure followed by a late provider error to test the proposed drain precedence. Mid-replay corruption must prevent result publication. Source-file mutation after production must not trigger a second source read; this is a no-replay test, not a source immutability claim.

No tests are authored or executed in this card. Root must review the explicit grant, error precedence and cleanup/recovery protocol before production admission. No source/provider contract is inferred from a plan or from an inert differential test.
