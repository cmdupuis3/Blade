## One implemented kernel

Only LLVM's ordinary array-return ABI can consume a new private immutable SameCellReturn certificate. It is constructed from the complete original IR function immediately before that function's emission, checked against the same function ID/body before use, and never stored in an optimizer/shared table or reused across compilations. New decision rule is `same-cell-return-llvm`, with one Applied/Declined record for each ordinary array-return attempt without an A03 generic return donor. C++ continues its original allocation path; no same-cell relationship enters generic ReturnDonors.

The complete grammar requires one direct fresh computed map of an original formal array, followed only by closed Float64 scalar observations/snapshots, at least one completed nonempty scalar fold over that donor, and one final computed scalar map reading exactly the donor. This is intentionally smaller than general last-use analysis. Initial kernel, fold kernel and final kernel are resolved direct callables with only scalar parameters/captures and closed literal/variable/+/-/* syntax. The typed bodies provide the totality proof even when synthesized lambdas have conservative Unknown summaries; an unresolved call/body or a failing operation is never assumed safe. Positive literal extent discharges unseeded-empty-fold failure. Original evaluation sites, scalar DAG and fold order remain unchanged.

Return, donor producer/input, tail/input, ArrayTypes and MethodFor metadata all pass strict unitless stored positive static rank-one Float64 role checks. Index equivalence uses IRTotality.sameIndex (named provenance agrees; anonymous IDs must agree). Loop metadata must match actual operands/types/identities and have exactly the ordinary scalar-map strategy, with no virtual/unit/layout conversion, triangular/tdim/Reynolds/co-iteration/parallel flags. Static, capturing, recursive, arity-polymorphic, CUDA/MPI/OMP functions/kernels are excluded. Parameter positions and unique parameter/capture/local identities are checked. Capture types are scalar and capture IDs must be completed earlier scalar values; scalar IR variables cannot hide index/array type payloads.

No alias/name/tuple/view, assignment, branch/loop, gather/stencil/scatter, deferred read, unknown call, effect or lifetime event fits the whole-body grammar. Embedded index extents are positive literals with no Dependencies. All other expressions or metadata decline rather than relying on a shallow count of donor IRVars. All callable capture lists and parameter/return/capture type payloads are also checked for a retained donor ID, including unused callables outside the function's expression tree. The recursive type check covers arrow slots, tuple/loop/computation/poly/unit/index-tag/distribution/group-key payloads, extent expressions and Dependencies. The source proof is deliberately conservative about alias copies: even a physically copied retained array name is excluded.

Owner checks cover existing generic donor map keys AND values, the current return donor, the complete return-donor map keys/values, known-ID HotRow/CellFold/RecStep/EpilogueLeg/Compaction/CompactRow plans, all MemberHoist plans' host/set/kernel IDs, and recorded OrbitPull audits among the complete body/reference IDs. Plan constructs that cannot fit the closed grammar also decline structurally. This is not a general audit of every external plan payload or an extension to any such schedule. No planner table is modified by production A04.

LLVM realization requires precisely one current ordinary pool scope and exactly one allocation/tracking entry: the completed donor APool, not a KnownIds input, row GEP, unknown pointer or latent AVirt. Its stored layout matches; no other ArrSlots entry aliases its root; its sole allocation-to-slot store has never been nulled/overwritten; all scalar snapshot slots are complete. Preflight emits nothing. Bind original lets/continuations once; on realization refusal materialize the original tail once. On admission prepare the original tail once and call unchanged fillDensePool with the donor pointer. That helper reads/coerces the scalar before storing to the same index. No new pool record, free, allocation identity or alias metadata is invented. Existing popPoolScope(Some returnedRoot) alone spares the one result owner.

Current LLVM counted-loop metadata makes no input/output disjointness claim. Allocator-only noalias remains attached to the original fresh allocation; parameters/array returns remain without noalias. Caller readonly is truthful because only the fresh local backing is written. C++ restrict/IVDEP/OMP code is untouched and receives no certificate. A03 independent-input returnPoolDestination, its Some-donor consumer and its decision rule remain unchanged, as do applyToArr/L1, dense fill, allocation/tracking and scope teardown helpers.
