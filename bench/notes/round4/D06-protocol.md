# D06 private sequential spool protocol (runtime prerequisite)

This checkpoint supplies a protocol library and standalone harness. It does not enable a compiler route, choose disk storage, omit an array, integrate a provider, add a CLI/environment option, or promise a performance gain. The earlier D06-census.md remains the approved design checkpoint; its proposed compiler failure-order policy is still future work.

## Capability and explicit grant

`blade_private_spool.hpp` supports native Windows host execution on an IEEE754 binary64 little-endian host, with an existing canonical ASCII fixed-local-drive scratch root. It rejects relative/UNC/noncanonical/reparse roots, paths whose serialized components exceed fixed buffers, and unsupported representations. The maximum full path buffer is 240 bytes including the terminator; a run name is exactly 47 ASCII characters. Root and run directory handles disallow delete sharing and are checked for canonical final path, regular directory attributes, volume and file identity. Other platforms return `unsupported` without file operations; this is not a portable owner-identity implementation. A trusted, user-controlled local scratch root is required; CRC and nonce are not authentication against an adversary with write access to that root.

A typed `Grant` explicitly supplies permission, root, memory allowance, disk quota, N, B and one rank-one axis identity token. Defaults grant no permission. There is no implicit temp directory or default disk use. B must be 1..1,048,576 cells. `plan` performs checked multiplication/addition and signed file-offset bounds before file creation/allocation. N=0 uses no data blocks. A large shape may be planned as metadata only, never materialized as a test payload.

The logical disk reservation is:

`72 + 64*G + 8*N + 64 + 128`, where `G=N/B + (N%B != 0)`.

It includes all file-format bytes, the fixed root-side ownership manifest (which is also the exclusive lock). This is a per-run logical file-byte quota, not an OS physical-block reservation or shared-root aggregate quota. Directory entries, filesystem allocation units and kernel buffers are outside that metric; physical disk-full still reports a checked native write/flush error. No free-space probe is treated as a reservation. Only one generation is active in this process; quota stays reserved until successful cleanup, including failed cleanup retries.

Tracked library workspace capacity is one `8*B` byte buffer, `sizeof(Control)` stable metadata and a 4096-byte reserve for this library's fixed local metadata. A static assertion caps Control at 4096 bytes. Native Windows internals and caller input/output buffers are outside that capacity metric; no process-RSS or total-program budget is claimed. No per-block vector, index or cleanup registration grows with G. At most four library OS handles are live: protected root/run directory handles, the exclusive owner-sidecar handle and a data/process/find handle. Recovery also uses the stable control slot and bounded metadata, and checks its memory grant. Busy counter snapshots have `available=false`; busy reservation inspection returns UINT64_MAX, never an apparent free reservation.

## Format and I/O

Version 1 is explicitly encoded little-endian bytes, not a serialized native struct or pointer. The fixed representation is IEEE754 binary64. Scalar bits pass through memcpy and integer byte encoding, preserving signed zero, subnormal, infinity and NaN payload bits without evaluating the floating value.

- Header (72 bytes): magic/version, N, B, G, axis token, two-word nonce and CRC64.
- Each block (64-byte header plus exactly 8*n_i payload bytes): sequence, global origin, expected element/payload lengths, nonce, payload CRC64 and header CRC64. Only the canonical full block or final short tail is accepted; zero-length append is an error.
- Footer (64 bytes): magic, final N/G/payload bytes, rolling payload CRC64, nonce and footer CRC64. Exact file length and EOF are checked; trailers/truncation refuse.
- Manifest (128 bytes): facility/version, owner PID and process-start identity, nonce, root/run volume and file IDs, logical reservation, N/B/axis, reserved field and CRC64.

CRC64/ECMA uses polynomial 0x42f0e1eba9ea3693, non-reflected, zero initialization and no final xor. The harness pins `123456789` to 0x6c40df5f0b497347. Integrity detects accidental byte changes, not hostile forgery. No nonfinite-value validation is invented for computed spool values.

Native transfers continue positive short reads/writes, stop on error or zero progress, and check all requested byte counts. Seal requires complete N/G, footer write, FlushFileBuffers, exact file size and successful CloseHandle. A close error cannot create a sealed token. Reopen verifies original data file identity, canonical ownership paths, exact size and complete header. Each payload block is checked before copying into the caller's destination. The final zero-count read is returned only after footer/EOF validation; `finish` is legal only then. Earlier valid blocks are borrowed computation input, not publication permission: a future terminal must keep its result private until full replay and finish succeed.

No crash-durable storage promise or fsync-style persistence guarantee is made. The spool is mandatory intermediate storage, so I/O/integrity errors are explicit statuses rather than cache misses or ignored stores.

## Unique ownership and cleanup

Move-only tokens enforce Writer -> Sealed -> Reader. Writer/Sealed are consumed by successful transitions, and the reader is single-use. Wrong-state calls refuse; append/read/seal failures poison the active phase until cancellation/cleanup. `cancel` is the cooperative cancellation point; no signal-handler filesystem work is provided. No source replay or source identity assumption exists.

A fixed process-owned Control slot holds copied paths and handles. Exit registration never points to a stack object. One atomic entry guard refuses overlapping calls; it does not spin or allocate. A concurrent process exit during an active operation reports incomplete cleanup and leaves ownership for explicit recovery rather than racing that operation. Tokens still require ordinary C++ single-owner use; sharing the same token object between racing callers is not supported.

`try_on_failure_exit` is the checked API added to blade_runtime.hpp. The old void `on_failure_exit` delegates to it and preserves callers' behavior. Mandatory spool startup checks capacity and installs one process-lifetime hook plus a checked atexit hook before opening scratch. Hook exhaustion/atexit failure reports a status without file creation. Partial registration is remembered so retries do not leak hook slots.

Explicit finish/cancel, RAII normal unwinding, atexit/std::exit and the runtime's private failure hook cover ordinary cleanup paths. Cleanup allocates no C++ memory, throws no exception and calls no diagnostic routine. A secondary failure uses bounded native stderr output from the exit callback, preserving the original runtime error and exit code. First protocol error and last cleanup attempt remain separately inspectable. Native handles that fail to close remain in the stable slot; the slot cannot be overwritten by another owner. Cleanup retries remain bounded.

Cleanup checks directory handles/identities and a bounded directory listing, refusing any unexpected entry or reparse point. Enumeration is used only to refuse: the run directory contains only the compiled-in `values.bin`. A fixed nonce-derived `<run-name>.owner` sidecar lives under the declared root and is held open exclusively as BOTH manifest and ownership lock. No path comes from serialized manifest text. Data deletion uses a verified file handle with reparse following disabled. The empty run directory is marked for deletion through its verified DELETE-capable handle, never a path-based RemoveDirectory call. Directory absence is confirmed before retiring the protected root handle and buffer. Only then is the owner sidecar marked and closed LAST. The sidecar stays readable/recoverable across data, directory, root-close and pre-disposition owner faults. No recursive delete or arbitrary-tree sweep exists; unexpected entries retain ownership evidence.

An abrupt kill, abort, external _Exit, host failure or filesystem outage can leave scratch. A crash during initial creation before a complete sidecar is flushed can leave incomplete evidence; it is NOT recoverable by inference. Once evidence is complete, cleanup retains it through all run-directory work and removes it only after all other resources are retired. A real failure of the final owner CloseHandle AFTER deletion was marked may leave only that delete-pending handle; OS process teardown can complete the deletion, so readable sidecar retention is not promised for this case. A separate injected close-after-success case returns a close error with scratch already absent and reservation zero; it reports failure after retirement, not a nonexistent recoverable manifest. Cleanup cannot promise deletion from an unavailable filesystem. Failures retain reservation/state while the process lives and do not claim that occupied bytes were reclaimed.

Recovery is an explicit call naming ONE recognized facility run directory under the supplied grant root. It does not search by age or enumerate directories to select work. It opens the exact root-side owner sidecar exclusively, validates name/nonce, fixed-length versioned manifest/CRC/descriptor, protected root identity, and owner PID plus process-start identity. If the run directory remains, its protected handle must match the recorded identity; if already removed by a late cleanup stage, recovery confirms absence and finishes retiring only the sidecar. A substituted directory or reparse point refuses. A held live lock refuses immediately. If the lock is available but the recorded PID/start pair is still live, it retains. A different process-start identity proves that recorded owner dead despite PID reuse. Failure to query identity/lock/liveness retains. Only after those checks can it unlink the fixed known files and non-recursively remove the directory. Unsupported platforms decline instead of relying on PID alone.
